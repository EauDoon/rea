# Daniel's decision workflows

For the customized EauDoon checkout, discover `diligence_stablecoin`,
`diligence_protocol`, `diligence_token`, `diligence_payments` and
`diligence_competitor` in the connected MCP prompt inventory. Retrieve the
appropriate prompt with the caller-selected `subject` and `decision_question`.
Optional `target_path`, explicit `target_kind`, `chain_context` and retained
`evidence_id` are selection data. Prompts never execute tools themselves.

Use the built local checkout for these additions; do not replace it with the
upstream npm package. When these prompts are absent, use the existing analysis
tools and the relevant questions in the repository's `docs/daniel-diligence.md`.
No global client configuration changes are necessary for a CLI investigation.

Route local EVM bytecode with an explicitly selected raw/hex encoding. Treat
recovered selectors, arguments and mutability as inferences. Bind chain, address,
implementation and block/time through separate primary evidence before stating
deployed behavior. Source/role reads, liquidity, position-specific sellability,
reserves, redemption terms, licensing and commercial terms are separate checks.

For shipped payment or competitor apps, analyze the supplied JavaScript/Electron
artifact, reuse retained Evidence, and trace a known route/API/module/string.
Use retained HAR inspection for captured flows. Static modules do not establish
executed payment behavior. Complete source repositories use ordinary source
inspection, without REA readiness or native provider commands.

Trace assets, effective authority, claims and obligations. Check ordinary exits
alongside adverse sequences. Separate reserve value, market depth, executable
liquidity and legal redeemability. Separate ledger credit, chain finality and
beneficiary settlement. Connect costs, yield, pricing and distribution to the
actor who gains, pays or bears the failure.

For a durable packet from the source checkout, build and run
`node scripts/daniel-diligence.mjs init --profile PROFILE --subject SUBJECT
--question QUESTION --out NEW_DIRECTORY`. Prefer ignored `_reference/diligence/`.
Add `--target PATH --kind evm-hex|evm-raw|javascript` only for a supplied local
artifact. The helper captures static Evidence and creates eight unknown coverage
questions. It does not execute the target or obtain external facts.

Edit claims and dated primary sources, then run
`node scripts/daniel-diligence.mjs report --case DIRECTORY`. The helper validates
record/citation integrity and keeps unknown coverage visible. It cannot decide
whether the cited evidence entails an analyst's claim. Review the emitted memo
before using it; a populated checklist supplies no assurance by itself.

Lead with the supported decision, concrete impact and missing evidence that
could change it. Include material preconditions, break paths, evidence, remedy
and reopen triggers. Use plain American English and Singapore time for human
dates. Never invent source facts, balances, rates, positions or probabilities.
Preserve the boundary between private diligence, public claims and execution.
